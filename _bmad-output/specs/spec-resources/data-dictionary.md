# Resources Data Dictionary

Database: `cras_resources` · PostgreSQL 18.6 · schema `public` · DDL: `schema.sql`.

This dictionary covers every table, column, enum, constraint, index, and trigger in the resources context. It is the implementation reference for the API and the BFF; `schema.sql` remains the executable source of truth.

## Conventions

| Concern | Rule |
|---|---|
| Table and column names | `snake_case`; plural table names. |
| JSON names | `camelCase`; e.g. `created_at` → `createdAt`, `resource_id` → `resourceId`. |
| IDs | `UUID` v4, server-generated by `gen_random_uuid()`, emitted lowercase. Clients never send IDs. |
| Timestamps | `TIMESTAMPTZ`; JSON is RFC 3339 UTC (`2026-10-26T23:34:19Z`). `createdAt` and `updatedAt` are server-set; `resolvedAt` is server-set on resolve. |
| Enums | Stored as uppercase labels; JSON values are the same uppercase strings. |
| Empty collection | A resource with no `resource_tags` rows; JSON `[]`. |
| Lists | Every JSON collection uses `{ "items": [...] }`; no pagination in v1. |
| Deletion | No API delete; `active=false` retires. Occurrence history is retained. |
| Timestamp trigger | `set_updated_at()` overwrites `updated_at` on every row update. |
| Code immutability | API rejects `code` on PATCH; trigger `trg_resources_code_immutable` is the database backstop. |
| Audit actors | `reported_by` and `resolved_by` hold employee UUIDs from the identity fragment. There is no cross-context FK; the employees context is not called. `reported_by` is set from the JWT and is immutable. |

## Enums

### `resource_type`

| Value | Meaning | Notes |
|---|---|---|
| `PROJECTOR` | A projector unit. | One physical unit. |
| `HEALTH_KIT` | A health or care kit. | One reservable unit; components and quantities are not modeled. |
| `COMPUTER` | A desktop computer or workstation. | One physical unit. |
| `NOTEBOOK` | A laptop. | One physical unit. |
| `CAMERA` | A camera or camcorder. | One physical unit. |
| `MICROPHONE` | A microphone, wired or wireless. | One physical unit. |
| `DISPLAY` | A monitor, TV, or projection screen. | One physical unit. |
| `CABLE` | A single cable. | One unit = one cable, not a bundle. |
| `ADAPTER` | An adapter, dongle, or converter. | One physical unit. |

There is no `ROOM` value. Room is a separate bounded context. `type` is descriptive: it never affects eligibility, which is `active` only.

There is deliberately **no `OTHER` fallback** (decision 2026-10-28). Every resource must fit one of the nine values; an unlisted kind of equipment requires an enum migration, not a catch-all. The trade-off is intentional: no unclassified rows, at the cost of a migration when a new kind of stock appears. Adding a value on an existing database uses `ALTER TYPE resource_type ADD VALUE '<VALUE>'` (commit before using it); removing a value requires recreating the type.

### `occurrence_type`

| Value | Meaning |
|---|---|
| `MALFUNCTION` | The resource does not work correctly. |
| `DAMAGE` | The resource has physical damage. |
| `MISSING` | The resource cannot be found. |
| `OTHER` | Any other occurrence. |

### `occurrence_status`

| Value | Meaning | Exit |
|---|---|---|
| `OPEN` | Recorded and not resolved. | May transition once to `RESOLVED`. |
| `RESOLVED` | Closed with a resolution, `resolved_by`, and `resolved_at`. | Terminal; no reopen. |

Transitions are literal: `OPEN → RESOLVED` only. Everything else is refused by the API and by `trg_occurrences_transitions`. There is no intermediate state: the `IN_PROGRESS` value was removed together with the assignee fields (decision 2026-10-28).

### `occurrence_priority`

| Value | Meaning | Default |
|---|---|---|
| `LOW` | Low operational urgency. | No |
| `MEDIUM` | Normal urgency. | Yes, on create when omitted. |
| `HIGH` | High operational urgency. | No |

Priority is staff-assigned. It does not gate reservations, auto-escalate, or change `active`.

## `resources`

One row = one physical reservable unit (Model A).

| Column | PostgreSQL type | Null | Default | JSON | Rules |
|---|---|---|---|---|---|
| `id` | `UUID` | No | `gen_random_uuid()` | `id` | Primary key. UUID v4, lowercase output, immutable. |
| `code` | `VARCHAR(32)` | No | — | `code` | Required on create. Unique. Uppercase. 3–32 chars. Pattern `^[A-Z0-9]+(-[A-Z0-9]+)*$`. Immutable after create. Input is trimmed and uppercased before validation. |
| `name` | `VARCHAR(120)` | No | — | `name` | Required. Trimmed, non-blank, 1–120 chars. |
| `type` | `resource_type` | No | — | `type` | Required. One of the enum values; no `ROOM`. |
| `active` | `BOOLEAN` | No | `TRUE` | `active` | The sole reservation gate. `false` retires the resource without deleting history. |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | `createdAt` | Server-set. The API rejects client-supplied values. Immutable in practice because no update path sets it. |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | `updatedAt` | Server-set by `trg_resources_updated_at` on every update. |

**Constraints.**

| Name | Type | Definition / effect |
|---|---|---|
| `resources_pkey` | Primary key | `id`. |
| `resources_code_unique` | Unique | `code`; SQLSTATE 23505 on duplicate. |
| `resources_code_upper` | Check | `code = upper(code)`. |
| `resources_code_format` | Check | `code ~ '^[A-Z0-9]+(-[A-Z0-9]+)*$'`. |
| `resources_code_length` | Check | `char_length(code) BETWEEN 3 AND 32`. |
| `resources_name_not_blank` | Check | `btrim(name) <> ''`. |

**Tags.** The multivalued tag attribute is normalized in `resource_tags` (0–10 rows per resource). The API still exchanges `tags` as a sorted array; the data layer reads and writes the child table in the same transaction.

## `occurrences`

One row = one fault, damage, missing, or other event attached to one Resource.

| Column | PostgreSQL type | Null | Default | JSON | Rules |
|---|---|---|---|---|---|
| `id` | `UUID` | No | `gen_random_uuid()` | `id` | Primary key. UUID v4, lowercase output, immutable. |
| `resource_id` | `UUID` | No | — | `resourceId` | FK to `resources.id`; `ON DELETE RESTRICT`. Immutable after create. |
| `description` | `TEXT` | No | — | `description` | Required. Trimmed, non-blank. No app-level maximum. |
| `type` | `occurrence_type` | No | — | `type` | Required. One of the enum values. |
| `priority` | `occurrence_priority` | No | `'MEDIUM'` | `priority` | One of the enum values; default on create. |
| `status` | `occurrence_status` | No | `'OPEN'` | `status` | Create → `OPEN`; resolve → `RESOLVED`. Never client-supplied. |
| `resolution` | `TEXT` | Yes | — | `resolution` | Required and non-blank when `RESOLVED`; must be `NULL` otherwise. No app-level maximum. |
| `reported_by` | `UUID` | No | — | `reportedBy` | Audit actor. Server-set from the JWT `employeeId` claim on create; never accepted in a body; immutable. |
| `resolved_by` | `UUID` | Yes | — | `resolvedBy` | Audit actor of the resolve. Server-set from the JWT `employeeId`; required when `RESOLVED`. |
| `created_at` | `TIMESTAMPTZ` | No | `now()` | `createdAt` | Server-set report time, not event time. The API rejects client-supplied values. |
| `resolved_at` | `TIMESTAMPTZ` | Yes | — | `resolvedAt` | Required when `RESOLVED`; `NULL` otherwise; never earlier than `created_at`. |
| `updated_at` | `TIMESTAMPTZ` | No | `now()` | `updatedAt` | Server-set by `trg_occurrences_updated_at` on every update. |

The three actor columns hold employee UUIDs from the shared identity fragment (`employeeId`). There is no foreign key to an employees table: the boundary is durable, and the resources context never calls the employees context. A UUID that does not exist in that context is stored as-is and surfaces as a display gap, not as a referential error.

**Constraints.**

| Name | Type | Definition / effect |
|---|---|---|
| `occurrences_pkey` | Primary key | `id`. |
| `occurrences_resource_fk` | Foreign key | `resource_id → resources(id) ON DELETE RESTRICT`; SQLSTATE 23503 on orphan or restricted delete. |
| `occurrences_description_not_blank` | Check | `btrim(description) <> ''`. |
| `occurrences_resolved_at_consistent` | Check | `RESOLVED` ⇒ `resolved_at IS NOT NULL`; non-`RESOLVED` ⇒ `resolved_at IS NULL`. |
| `occurrences_resolution_matches_status` | Check | `RESOLVED` ⇒ `resolution IS NOT NULL AND btrim(resolution) <> ''`; non-`RESOLVED` ⇒ `resolution IS NULL`. |
| `occurrences_resolved_by_matches_status` | Check | `RESOLVED` ⇒ `resolved_by IS NOT NULL`; non-`RESOLVED` ⇒ `resolved_by IS NULL`. |
| `occurrences_resolved_after_created` | Check | `resolved_at IS NULL OR resolved_at >= created_at`. |

**Lifecycle.**

| From | To | Action | Allowed input fields | Server-set fields | Forbidden |
|---|---|---|---|---|---|
| — | `OPEN` | create | `description`, `type`, `priority` | `id`, `reported_by`, `created_at`, `updated_at` | `status`, `resolution`, `resolvedAt`, `resolvedBy`, `reportedBy` |
| `OPEN` | `RESOLVED` | resolve | `resolution` | `status`, `resolved_by`, `resolved_at`, `updated_at` | `status` as input, reopen, editing `description` |
| `RESOLVED` | — | any | none | — | any write; second action returns 409 |

**Delete behavior.** No API delete. There is no cascade from resources; the FK is RESTRICT. A resolved occurrence remains forever in v1. `trg_occurrences_terminal_state` refuses any direct database UPDATE of a `RESOLVED` row; `trg_occurrences_transitions` refuses illegal status changes; the API never attempts either. A direct DELETE is an operational decision outside the API contract and is not blocked by the trigger.

## `resource_tags`

One row = one tag of one resource. 1NF model for the multivalued `tags` attribute.

| Column | Type | Null | Default | Rules |
|---|---|---|---|---|
| `resource_id` | `UUID` | No | — | FK `resources(id) ON DELETE CASCADE`. Part of the primary key. |
| `tag` | `VARCHAR(30)` | No | — | Lowercase, non-blank, 1–30 chars, pattern `^[a-z0-9]+(-[a-z0-9]+)*$`. Part of the primary key. |

**Constraints and indexes.**

| Name | Type | Effect |
|---|---|---|
| `resource_tags_pkey` | Primary key | `(resource_id, tag)`; prevents duplicate tags. |
| `resource_tags_tag_not_blank` | Check | `btrim(tag) <> ''`. |
| `resource_tags_tag_lower` | Check | `tag = lower(tag)`. |
| `resource_tags_tag_format` | Check | `tag ~ '^[a-z0-9]+(-[a-z0-9]+)*$'`. |
| `resource_tags_tag_length` | Check | `char_length(tag) BETWEEN 1 AND 30`. |
| `idx_resource_tags_tag` | Index | Supports exact tag lookup. |
| `trg_resource_tags_max` | Trigger | `BEFORE INSERT`; refuses an 11th tag for the same resource. |

**Write semantics.** Create inserts one row per tag in the same transaction as the resource. PATCH deletes all rows for the resource and reinserts the submitted set. A duplicate tag is impossible by primary key; the API still de-duplicates before writing so the failure is a 422, not a 23505. **Delete semantics.** Deleting a resource removes its tags (CASCADE); the API never deletes, and occurrences keep their RESTRICT.

## Functions and triggers

| Object | Kind | Purpose |
|---|---|---|
| `set_updated_at()` | PL/pgSQL function | Sets `NEW.updated_at := now()`; returns `NEW`. |
| `trg_resources_updated_at` | Trigger | `BEFORE UPDATE` on `resources`, row-level. |
| `trg_occurrences_updated_at` | Trigger | `BEFORE UPDATE` on `occurrences`, row-level. |
| `prevent_resource_code_change()` | PL/pgSQL function | Raises `resources.code is immutable` when `NEW.code IS DISTINCT FROM OLD.code`; SQLSTATE P0001. |
| `trg_resources_code_immutable` | Trigger | `BEFORE UPDATE OF code` on `resources`, row-level. |
| `prevent_resolved_occurrence_change()` | PL/pgSQL function | Raises `resolved occurrences are immutable`; SQLSTATE P0001. |
| `trg_occurrences_terminal_state` | Trigger | `BEFORE UPDATE` on `occurrences` with `WHEN (OLD.status = 'RESOLVED')`, row-level; backstops no reopen and no edit-after-resolve. |
| `prevent_illegal_occurrence_transition()` | PL/pgSQL function | Allows only `OPEN → RESOLVED`; raises `illegal occurrence transition` otherwise. |
| `trg_occurrences_transitions` | Trigger | `BEFORE UPDATE OF status` with `WHEN (OLD.status IS DISTINCT FROM NEW.status)`, row-level. |
| `prevent_occurrence_identity_change()` | PL/pgSQL function | Raises when `resource_id` or `reported_by` changes; SQLSTATE P0001. |
| `trg_occurrences_identity_immutable` | Trigger | `BEFORE UPDATE OF resource_id, reported_by`, row-level. |
| `enforce_resource_tags_max()` | PL/pgSQL function | Raises `a resource may have at most 10 tags` when the resource already has 10. |
| `trg_resource_tags_max` | Trigger | `BEFORE INSERT` on `resource_tags`, row-level. |

`created_at` is server-set by the API. The database default is a backstop; there is no trigger that rewrites it. Any database client that bypasses the API can supply it, which is outside the contract.

## Indexes

| Index | Table | Columns / method | Serves |
|---|---|---|---|
| `resources_pkey` | `resources` | `id` B-tree | Primary key lookup. |
| `resources_code_unique` | `resources` | `code` B-tree unique | Code lookup and duplicate prevention. |
| `idx_resources_active_type` | `resources` | `(active, type)` B-tree | Active and active+type filters. |
| `idx_resource_tags_tag` | `resource_tags` | `tag` B-tree | Exact tag filter via `EXISTS`/join on `resource_tags`. |
| `occurrences_pkey` | `occurrences` | `id` B-tree | Primary key lookup. |
| `idx_occurrences_resource_status` | `occurrences` | `(resource_id, status)` B-tree | Open-occurrence counting and status filter for one resource. |
| `idx_occurrences_resource_created_at` | `occurrences` | `(resource_id, created_at DESC)` B-tree | Aggregate occurrence list ordered newest first. |
| `idx_occurrences_status_priority` | `occurrences` | `(status, priority)` B-tree | Open and in-progress queue ordered by priority; not exposed by v1 routes. |

A type-only filter may not use `idx_resources_active_type` because `type` is the second column; the catalog is small in v1 and the query remains correct. A future type-only index is an optimization, not a contract change.

## Validation matrix

| Rule | Invalid example | Expected result |
|---|---|---|
| Code uppercase | `proj-01` | API normalizes to `PROJ-01`; direct DB insert is rejected by `resources_code_upper`. |
| Code length | `AB` or 33 chars | API 422; DB check violation. |
| Code pattern | `PROJ_01`, `-PROJ`, `PROJ--01` | API 422; DB check violation. |
| Code unique | second `PROJ-01` | API 409 `FR-22` / `RESOURCE_CODE_TAKEN`; DB 23505. |
| Code immutable | `UPDATE resources SET code = 'NEW-01'` | API 422 when `code` is in PATCH; DB raises P0001. |
| Name non-blank | `'   '` | API 422; DB check violation. |
| Name length | 121 chars | API 422; DB `VARCHAR(120)` error. |
| Type | `ROOM` or unknown | API 422; DB enum error. |
| Tags count | 11 tags | API 422; DB trigger `trg_resource_tags_max` raises P0001. |
| Tag lowercase | `AV` | API normalizes; DB check violation if bypassed. |
| Tag length | 31 chars | API 422; DB varchar/check violation. |
| Tag pattern | `audio visual` | API 422; DB check violation. |
| Tag duplicate | `['av','av']` | API deduplicates; DB primary key violation if bypassed. |
| Tag element null | `NULL` in the array | API 422; `resource_tags.tag` is `NOT NULL`. |
| Tag on missing resource | insert with unknown `resource_id` | DB 23503 FK violation; API 404. |
| Occurrence orphan | `resource_id` not present | API 404; DB 23503. |
| Description blank | `'   '` | API 422; DB check violation. |
| Occurrence type | `BROKEN` | API 422; DB enum error. |
| Priority | `URGENT` | API 422; DB enum error. |
| Create status | client sends `status`, `reportedBy`, `resolvedBy`, or `resolution` | API 422 (unknown client field); DB create path always uses the defaults. |
| Reporter missing | API maps a token without `employeeId` to 403 `AUTH_FORBIDDEN` / `EMPLOYEE_IDENTITY_REQUIRED`; a direct insert without `reported_by` violates `NOT NULL`. |
| Resolve without resolution | `RESOLVED`, `resolution NULL` | API 422; DB check violation. |
| Resolve without `resolved_at` | `RESOLVED`, `resolved_at NULL` | DB check violation. |
| Resolve without `resolved_by` | `RESOLVED`, `resolved_by NULL` | DB check violation. |
| Open with `resolved_at` | `OPEN`, `resolved_at NOT NULL` | DB check violation. |
| Resolve before create | `resolved_at < created_at` | DB check violation. |
| Second resolve | `RESOLVE` on `RESOLVED` | API 409 `FR-22` / `OCCURRENCE_ALREADY_RESOLVED`; DB update would violate the resolution/status checks if it cleared fields, so the API must refuse. |
| Removed state | `IN_PROGRESS` as a value | DB enum error; the API enum has no such value. |
| Illegal transition | any status other than `OPEN → RESOLVED` | DB trigger `trg_occurrences_transitions` raises P0001; the API has no action for it. |
| Reporter rewrite | `UPDATE occurrences SET reported_by = ...` | DB trigger `trg_occurrences_identity_immutable` raises P0001; the API never accepts the field. |
| Reopen or edit resolved | `UPDATE occurrences SET status='OPEN' ...` on a RESOLVED row | DB trigger `trg_occurrences_terminal_state` raises P0001; API has no route. |
| Resource delete with occurrences | `DELETE FROM resources ...` | DB SQLSTATE 23001 (`restrict_violation`) due to `ON DELETE RESTRICT`. |
| Occurrence delete | any delete | No API route; direct DB delete is outside the contract and not exposed. |

## API-to-database mapping

| Operation | Database effect |
|---|---|
| `GET /v1/resources` | `SELECT ... FROM resources` with AND filters; `code` uppercased; `tag` matched with `EXISTS (SELECT 1 FROM resource_tags t WHERE t.resource_id = resources.id AND t.tag = $tag)`; `ORDER BY code ASC`. Tags loaded with a second query for the returned page. |
| `POST /v1/resources` | `INSERT INTO resources (code, name, type, active) VALUES (...)` plus one `INSERT INTO resource_tags` per tag, in one transaction; defaults fill `id`, `created_at`, `updated_at`, `active`. |
| `GET /v1/resources/{id}` | `SELECT` resource; `SELECT` occurrences `WHERE resource_id = $1 ORDER BY created_at DESC, id DESC`. |
| `PATCH /v1/resources/{id}` | `UPDATE resources SET` only supplied fields; `tags` deletes and reinserts `resource_tags` rows in the same transaction; `updated_at` trigger fires; `code` never in the SET list. |
| `POST /v1/resources/{id}/occurrences` | `INSERT INTO occurrences (resource_id, description, type, priority, reported_by) VALUES (...)`; `status` default `OPEN`; `created_at`/`updated_at` defaults. |
| `PATCH .../{occurrenceId}` | `UPDATE occurrences SET status='RESOLVED', resolution=$1, resolved_by=$2, resolved_at=now() WHERE id=$3 AND resource_id=$4 AND status='OPEN'`; zero rows: read the row to distinguish 404 from 409. |
| BFF `openOccurrenceCount` | `SELECT count(*) FROM occurrences WHERE resource_id=$1 AND status='OPEN'`, or count the occurrences returned by the aggregate. |
